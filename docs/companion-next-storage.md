# Companion Next · 存储规范（阶段 02）

状态：待审核。基线：[产品原型 PR #26](https://github.com/Routilet/accoding-companion/pull/26)。维护者确认隐藏目录、版本化 expanded.h、不兼容旧 .accoding；其他细节为本轮建议。

## 1. 文件优先

打开目录是导航，不是注册。打开单文件时选择其直接父目录。当前目录及当前文件仅为应用会话状态；任意普通 C/C++ 文件无需初始化。读取目录/源文件不写入任何辅助数据。

```text
C语言课程/
├── A.c
├── B.c
├── .companion/
│   ├── cases/
│   │   ├── A.c.json
│   │   └── B.c.json
│   └── resources/
│       ├── 0.6.10/
│       │   ├── expanded.h
│       │   ├── manifest.json
│       │   ├── reference.json
│       │   └── manual.zh-CN.md
│       └── 0.7.0/
│           └── ...
└── 第一次作业/
    ├── A.c
    └── .companion/cases/A.c.json
```

版本号仅为示意。旧版 .accoding 完全不读取、不写入、不迁移；旧版独立可用。新产品名 Companion；仓库/npm 实际重命名仍由组织发行迁移阶段协调，本轮不执行。点目录在 Unix 隐藏，Windows 创建时设置 .companion 的 hidden 属性（失败不阻止使用）；不改变其他目录属性。文件树排除 .companion、.accoding 和临时产物。默认递归按需展开子目录，不遍历目录链接/重解析点；源文件链接不纳入首版写操作。只允许当前导航树内的普通文件，显式打开其他文件时切换父目录。

## 2. 样例

关联键 = 源文件实际父目录 + 完整文件名（含扩展名），使用文件系统自身大小写语义，不强制转小写。A.c 与 A.cpp 分别保存。始终存到父目录/.companion/cases/<完整文件名>.json，无论从何处打开该文件。

```json
{
  "schemaVersion": 1,
  "cases": [
    {"input":"5\n1 2 3 4 5\n","expected":"15\n"},
    {"input":"","expected":""},
    {"input":"0\n","expected":null}
  ]
}
```

UTF-8 JSON、顺序即样例编号。input 必须为字符串；expected 必须为字符串或 null，null 不比较，空字符串明确比较空输出（按统一比较规则）。不增加 UUID、名称、来源、时间、OJ 字段或历史结果。读取缺失文件返回空列表，不写盘；显式保存才创建目录。保存空列表也保留有效 JSON，不自动删除用户数据。损坏/未知 schema/无权限返回明确错误，不以空列表替代，不覆盖；用户可手动修复或另存。保留用户输入原始换行和空格，不自动添加换行；程序 stdin 写入后关闭。

保存按同目录临时文件 + 原子替换（Windows 使用可靠替换语义），失败保留原数据；以原文件字节摘要作为读取修订号，保存前检查并发修改，应用同进程串行、跨进程写锁；冲突提示重新读取，不静默合并。不建数据库、全局索引、根目录注册文件。

## 3. 重命名、移动与恢复

路径关联不是永久文件身份。同路径重用意味着沿用原样例；如果会话中明确观察到删除/重新创建，则提示该路径有旧样例，等待确认，不把它当新文件的已验证结果。应用关闭时无法区分同名替换与修改，这个限制必须明确；不承诺任意操作后正确识别身份。

- 应用内重命名：只在同目录，检查源与目标及两侧样例冲突（包括文件系统大小写语义）；首版不支持跨目录移动。先保留旧样例，执行源重命名，再以不覆盖方式移动样例；失败时尝试回滚源，若回滚失败明确报告两处路径，原样例仍保留。大小写仅变化若平台不支持直接改名则提示外部操作，不加复杂中转。
- 外部重命名：首版不自动迁移样例。监视事件/重新扫描仅刷新导航和失效状态；编辑器原子保存常表现为 rename，不能据此猜测文件身份。删除/移动不删除样例。
- 当前文件没有样例且同目录存在未关联 JSON 时，显示轻量“恢复测试数据”入口，用户选择旧文件名后复制样例至当前文件（保留原文件，不覆盖）。跨目录时可显式选择 JSON 导入，已有样例时须明确追加或取消，不自动覆盖；无全局搜索或专门孤立数据管理页。源文件内容哈希不用于身份匹配。
- 目录整体移动且相对布局不变时，数据随目录移动。单独移动源文件不保证样例或头文件随行。外部删除后原数据保留；不自动垃圾清理。

## 4. Exam Kit

新建 C：默认使用 Routilet 当前激活且已安装的 C99 资源版本，在当前打开的目录下 .companion/resources/<version>/ 创建/复用快照；若新文件在子目录，则生成相对 include 路径，分隔符 /。直接打开子目录后新建文件可在其本地建立快照，不强求跨根去重。已有文件的 include 解析始终以源文件父目录为准，和当前打开目录无关。例如：

```c
#include ".companion/resources/0.6.10/expanded.h"
```

新版新建文件不得引入旧 .accoding 路径；C++ 仅普通模板。资源缺失先提示通过 Routilet 准备，不自动下载、不新建坏文件。新建采用独占创建，不覆盖。资源先准备成功再写源文件；失败仅可能留下可复用资源快照。

版本目录内保留现行 manifest、完整 expanded.h、manifest 引用的组件文件（inline v2 已在 manifest 内，不重复生成）、现有 reference/manual；版本键采用受验证的安装包版本，不能逃逸路径。快照以暂存目录、校验、同卷原子发布；同版本已有内容一致则复用，不一致则报错，禁止静默覆盖。验证 manifest、组件、依赖拓扑、路径和完整头文件是否与生成内容一致；拒绝链接逃逸。指纹覆盖全部所需资源；安装目录更新不会修改快照。缺失/损坏快照可由用户主动使用完全相同版本及内容恢复，不能自动替换版本。已有源码只根据显式 include 识别资源；不建立文件版本绑定表。手册优先当前文件快照，无资源引用则读取当前已安装版本。

## 5. 其他状态

应用全局配置放系统用户配置目录 Companion（Windows LocalAppData；macOS Application Support），只保存最近目录、相对选中文件、编译器/编辑器设置；无用户数据索引。原子写入；启动恢复失败则空状态。测试结果、源码快照及运行 ID 仅在会话内保存；关闭后重新测试，不持久化 AC/历史。临时编译文件在系统临时目录的独立运行目录中，成功、失败、取消均清理，不删除用户文件。卸载/更新不删除用户目录内数据。

## 6. 验收

无写打开；中文路径、空格、同名不同后缀、不同层级打开同一文件；空/null 用例区分；损坏 JSON 与并发写冲突；重命名目标冲突与故障回滚、外部移动后保留恢复；两版本并存、打开子目录、移动整个目录、资源缺失与篡改；旧 .accoding 原样保留。双平台文件语义、原子替换及隐藏属性需实测。
